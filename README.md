## 비교 사이트 & 리뷰 도구

**풀이 파일은 지금까지 하던 대로 올리면 됩니다.** 폴더 구조도 커밋 메시지도 그대로입니다.
아래는 그 위에 얹은 도구입니다.

### 올릴 때 — 브랜치 안 팝니다

지금까지처럼 `main` 에 바로 push 하면 됩니다. 브랜치도 PR도 만들지 마세요.
다만 push 전에 한 번만 아래를 설정해두면 "rejected" 로 막히는 일이 없어집니다.

```bash
git config --global pull.rebase true
```

각자 **본인 이름 폴더의 `.java` 만** 건드립니다.
`scripts/`, `site/`, `reviews/`, `data/` 는 도구 쪽이라 서로 부딪히지 않습니다.

### 사이트 보기

`git pull` 한 뒤 `site/index.html` 을 더블클릭하면 열립니다. 서버도 설치도 필요 없습니다.

같은 문제를 푼 사람들의 코드가 나란히 뜹니다.
**리뷰는 코드 아래 `리뷰 보기` 버튼을 눌러야 나옵니다** — 먼저 코드를 읽고,
자기 생각을 정한 뒤에 펼쳐 보라고 일부러 접어뒀습니다. 판정과 태그도 그 안에 있습니다.

**리뷰가 다 채워진 문제부터 보려면** 목록 상단의 `리뷰 있는 문제만` 을 체크하세요.
지금은 4문제입니다 — 보급로, 다단계 칫솔 판매, 입국심사, 디스크 컨트롤러.

상단 탭에서 **사람별**(반복 지적 패턴 Top 5), **로테이션**(미제출 현황)도 볼 수 있습니다.

### 스터디를 떠난 사람

`data/authors.json` 에서 그 사람에게 `"active": false` 를 달면 됩니다.

올려둔 코드와 리뷰는 **지워지지 않고 그대로 남습니다** — 비교 자료로 계속 쓸 수 있습니다.
다만 기본 화면에서 감춰지고, 미제출 현황과 발표 로테이션에서는 빠집니다.
헤더의 `졸업생 포함` 을 체크하면 다시 보입니다.

돌아오면 `active` 를 `true` 로 되돌리면 끝입니다.
`data/rotation.json` 의 `order` 에서도 빼야 발표 순번이 그 사람 차례에서 멈추지 않습니다
(`node scripts/check.mjs` 가 확인해줍니다).
